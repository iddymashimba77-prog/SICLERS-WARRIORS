## 2. Design System (centralized)

New canonical tokens — single source of truth under `lib/core/theme/`:

| Token | Value | Notes |
|---|---|---|
| Navy `navy` | `#0B1F3D` | top bars, headings, navigation, selected states |
| Blue `blue` (primary) | `#1B5FAE` | primary actions, links, progress, interactive states |
| Emergency Red `emergency` | `#C81E3A` | SOS / blood / critical only — never a primary surface |
| `emergencyContainer` | `#FCEBEE` | emergency icon/indicator tint |
| Background / Surface | `#F5F7FA` / `#FFFFFF` | plus `surfaceMuted` |
| Success / Warning / Info | `#2E7D32` / `#EF6C00` / `#1B5FAE` | accessible green/amber/blue |
| Text | `textPrimary #1B2433`, `textSecondary`, `textMuted`, `textDisabled`, `textOnDark`, `textOnBlue`, `textOnEmergency` | |
| Borders | `border #E2E8F0`, `borderSubtle`, `divider` | |

Supporting systems in `lib/core/theme/`:
- **`app_spacing.dart`** — scale `xxs 2 … huge 64`, `screenEdge 16`, `contentMaxWidth 1200`, `gapW`/`gapH` helpers.
- **`app_typography.dart`** — named roles (display, headline, title, body, label, button …) and a brightness-aware `TextTheme` (dark-mode-ready).
- **`app_shapes.dart`** — small 8 / medium 10 / card 16 / large 20 / bottom-sheet top radius.
- **`app_theme.dart`** — rebuilt `ThemeData`: explicit light/dark `ColorScheme` (no seed color), navy `AppBar`, blue primary buttons, themed navigation bar/rail, inputs, cards, dialog, snackbar, chips/badges, progress, switch/checkbox/radio, menu, tooltip, `InkSparkle` splash. All surfaces read the tokens, so dark mode is a drop-in.

Responsive system in `lib/core/responsive/responsive.dart`: `AppScreenSize`
(compact <600, medium <1024, expanded <1440, large ≥1440), `AppLayout`
helpers (`useBottomNavigation`, `showRailLabels`, `columnCount`, `edgePadding`),
`ResponsiveBuilder`, `ContentColumn`.

Icon system: a single family (`material` `Icons.*`), consistently outlined;
assets remain an organized folder (nothing copyrighted was downloaded).

## 3. Global Components (`lib/shared/widgets/`)

- **Cards:** `AppCard` / `AppCard.action`; dashboard blocks (`StatCard`/`StatGrid`,
  `ProgressCard`, `HealthSummaryCard`, `QuickAction`/`QuickActionsGrid`,
  `SectionHeader`, `TimelineItem`, `AlertCard` (non-emergency tone variants),
  `RecommendationCard`); domain variants (`MedicationCard`, `AppointmentCard`,
  `EducationCard`, `DonationCard`, `BloodCard`) — reusable vocabulary, no feature logic.
- **Controls:** `AppSearchField`, `AppFieldLabel`, `AppHelperText`,
  `AppFilterChip`, buttons (Filled/Elevated/Outlined/Text themed globally).
- **Status/feedback:** `AppBadge` (icon + label, never colour-only), `AppAvatar`,
  `AppTopBar` (navy, back/title/notification-badge/avatar/actions),
  `AppHomeHeader` (personalized navy greeting header),
  `confirmAction()` / `showSuccess()` / `showToast()` / `showBanner()`,
  `SosButton` + `EmergencyCard` (emergency-red, two-stage confirm, distinct look, `Semantics` label).
- **States:** `LoadingView`, `ErrorRetryView` (friendly copy, never raw
  exceptions/stack traces/backend details), `EmptyStateView` (icon + explanation
  + optional action), plus calm, non-animated skeletons (`SkeletonBox`,
  `SkeletonLine`, `SkeletonCard`, `SkeletonListView`) — no blank screens, no
  excessive animation, no looped shimmer.

**Medical safety & accessibility:** status is never conveyed by colour alone;
badges/indicators carry icons + text; SOS is visually unmistakable and hardened
against accidental triggering; copy is outcomes language (no implied diagnosis);
AI/diagnostic surfaces remain separate and labeled in later stages.

## 4. Application Shell & Patient Shell (`main_shell.dart`)

Adaptive patient shell with **exactly** the five approved destinations and an
always-visible SOS action:

| # | Label (Swahili) | Destination |
|---|---|---|
| 1 | **Nyumbani** (Home) | `HomePage` — personalized header + quick actions + explore launchers (dashboard foundation) |
| 2 | **Daktari** (Doctor) | `DoctorHubPage` — light landing → Doctor Network / Clinic calendar / Messages (existing pages) |
| 3 | **Tiba** (Treatment) | `HealthDashboardPage` (existing) |
| 4 | **Changia** (Donate) | `ChangiaHubPage` — light landing → Blood Donation / Financial Donations (existing pages) |
| 5 | **Wasifu** (Profile) | `ProfilePage` (existing) |

- **compact (<600):** top bar + `NavigationBar` bottom nav.
- **medium+ (≥600):** `NavigationRail` (extended labels ≥1024) + `VerticalDivider`.
- Bodies sit in an `IndexedStack` so each destination **preserves navigation state**.
- Global red **SOS FAB** (`tooltip: AppStrings.sos` → `EmergencyPage`) on every size.
- New hub routes `/daktari` and `/changia` registered in `app.dart`; existing routes untouched.

New `HomePage` is foundation-only: `AppHomeHeader`, quick-actions grid, launcher
cards and an `EmergencyCard` — the full personalised dashboard is deliberately
FRONTEND-2.

## 5. Admin Shell Foundation (`admin_shell.dart`)

A separate desktop-first surface: dark-navy collapsible `AdminSidebar` with
active state, brand mark, nav (Overview, Users, Verifications, Content,
Campaigns, Reports, Settings), bottom profile area; `AppTopBar` with
notifications/avatar; content area shows a lightweight operational overview and
labeled placeholders for later admin modules. Narrow windows fall back to a
drawer. `AdminPanelPage` now hosts the shell behind a `RoleGate`
(ADMIN/SUPER_ADMIN only) and a safe no-access fallback.

**Role-aware foundation** (`role_gate.dart`): `AppRoles` constants + `RoleGate`
widget keyed off `AuthController.roles`. No login role dropdown; roles come from
the authenticated session; the backend remains the security authority.
