## 1. Scope

An engineering pass (no new user-facing features). Every change is traceable to
an NFR and each is proven end-to-end by the `performance` test app and
`stage418_gate.py`. Themes:

1. **Query-count discipline (NFR-PERF-001/SCAL-001).** Replace per-row (N+1)
   counting with **batch/grouped aggregations**, active-materialisation, and
   correlated subqueries so request cost is **independent of row volume**.
2. **Reference caching (NFR-PERF-001, privacy-safe).** Static vocabulary is
   cached with a strict "reference-only" policy; **no user-scoped data is ever
   cached**, and cache failure **degrades to a direct loader**, never a 5xx.
3. **Global capped pagination (NFR-PERF-002).** One project-wide pagination
   class (page 20, `page_size` honoured, hard cap 100) plus lean list payloads
   (education list drops the full HTML body) and a bounded analytics scan window.
4. **Async job queue (NFR-PERF-003).** Durable, DB-backed jobs with exclusive
   claim, stale-run re-claim, capped exponential backoff, max-attempts → FAILED;
   the analytics daily aggregation is the first registered task.
5. **Indexes (NFR-PERF-001).** Two additive indexes on the proven hot filters
   (blood donor directory, education published/category feed); all other hot
   paths already exercised existing approved indexes — no redundant ones.
6. **Health observability (NFR-AVL-002).** Readiness now probes the **live
   cache** (set/get round-trip) and every response carries
   `X-Duration-Ms`/`X-Query-Count`; opt-in duration/query logging.
7. **Mobile education efficiency (NFR-PERF-001).** Bookmarks fetch in **parallel**
   with per-article error isolation; the content list passes pagination params.

## 2. What was delivered

**Backend — `config/settings/base.py`**
- `DEFAULT_PAGINATION_CLASS` → `core.pagination.CorePageNumberPagination`
  (page 20 default; `page_size` allowed; `max_page_size = 100`).
- `CACHES`: env-configurable default (`LocMemCache`, optional Redis via
  `CACHE_BACKEND`/`CACHE_URL`/`CACHE_KEY_PREFIX`/`CACHE_TIMEOUT`).
- Resource limits: `DATA_UPLOAD_MAX_MEMORY_SIZE = 2_621_440`,
  `DATA_UPLOAD_MAX_NUMBER_FIELDS = 1000`; `CONN_MAX_AGE` env-tunable (0 default).
- `"performance"` added to `PROJECT_APPS`/`INSTALLED_APPS`;
  `core.middleware.PerformanceLogMiddleware` appended after the correlation-id
  middleware.

**Backend — core (new infra)**
- `core/cache.py` — `reference_get/set/invalidate_reference` + key/TTL constants
  (education categories, symptom types). Reference-only policy; failures fall
  back to the direct loader.
- `core/caching.py` — `ReferenceCachedListMixin` (caches the serialized list,
  re-paginates on hit; used by the education categories endpoint).
- `core/models.py` `BackgroundJob` + `core/migrations/0001_initial.py`.
- `core/jobs.py` — `enqueue/process_due/job_handler`: `select_for_update` claim
  (at-least-once), stale `RUNNING` re-claim after 900 s, backoff
  `min(300, 30 · 2^(attempts-1))`, max-attempts → `FAILED`, unknown task →
  `FAILED`. `core/tasks.py` registers `analytics.sync` (calls `compute_daily`).
- `core/management/commands/process_jobs.py` — worker entry
  (`--limit/--task/--seconds`, idempotent, safe when run concurrently).
- `core/views.py` — `health_ready` now does a real cache set/get round-trip and
  returns **503 degraded** (never 5xx, never fake-ok) when the cache is down.
- `core/middleware.py` — `PerformanceLogMiddleware`: always sets
  `X-Duration-Ms` + `X-Query-Count`; duration/query logging only when
  `PERF_LOG_ENABLED=1`.

**Backend — hot-spot optimisations**
- `medications/services.py` — `_counts_for_medications` (one grouped query
  across `schedule_id`/`status` replaces per-medication loops) used by
  `dashboard`, `adherence_stats`, `_adherence_block_batch`; materialised
  `list(...)` for QR codes.
- `notifications/services.py` — `create_broadcast_notifications` = a **single
  `bulk_create(batch_size=500)`**; `notifications/admin_views.py` broadcast uses it.
- `ai_assistant/admin_views.py` — monitoring aggregation: one grouped query
  (action_code/result) + one distinct-actor query (was ~6 scans).
- `analytics/services.py` — `_MAX_SERIES_DAYS = 366`; series clamps a missing
  `date_from` to 366 days (bounded scan).
- `emergencies/views.py` — admin monitor: `select_related("requester","patient")`
  + `MONITOR_FEED_LIMIT = 100` bounded feed (response shape preserved);
  `EmergencyRequestViewSet` / `EmergencyAccessGrantViewSet` querysets annotated
  with `select_related`.
- `education/serializers.py` — `EducationalContentListSerializer` (no `body`);
  `education/views.py` list uses it while detail keeps the full body.
- `community/views.py` — reaction/comment counts switched from
  `Count(DISTINCT …)` joins to **correlated `Subquery`** counts.

**Backend — indexes (additive)**
- `blood_network/migrations/0005_...bld_donor_verified_cnt_idx.py` —
  `is_verified, -donation_count` (donor directory sort).
- `education/migrations/0004_...edu_content_status_cat_pub_idx.py` —
  `status, category, -published_at` (published feed + category filter).
- Audited existing indexes already covered: notification inbox
  (recipient,status,-created_at), message threads, audit action/actor scans,
  emergency status/severity/created_at, comment threads, health timeline
  patient ordering, medication-event schedule/broadcast-time ordering — **no
  duplicate indexes added**.

**Backend — `performance` app (new, 28 tests + measurement harness)**
- `performance/tests.py` — pins settings defaults, pagination caps (20 / param /
  cap 100), education lean list + categories cache hit (**0 queries on 2nd hit**)
  + invalidate re-seed, AI monitoring ≤ 2 audit selects, dashboard/adherence
  bounded query budgets, broadcast **single INSERT**, job-queue lifecycle
  (success / retry+backoff / max-attempts FAILED / unknown-task FAILED / claim
  exclusivity), health readiness + degraded path + perf headers, reference-cache
  round-trip/invalidate.
- `performance/management/commands/measure_perf_baseline.py` — reproducible
  endpoint matrix (10 probes) printing status/queries/ms; **refuses any
  non-SQLite engine**.

**Mobile — education efficiency**
- `apps/mobile/.../education_bookmarks_page.dart` — parallel `Future.wait`
  fetch with per-article isolation (a 404 no longer drops the whole list).
- `apps/mobile/.../education_repository.dart` — `listContent` accepts
  `page`/`pageSize` (server caps at 100).
- `apps/mobile/test/stage411_education_test.dart` — +2 tests (pagination params;
  concurrent fetch with a 404 skip). **65 Flutter tests green.**

**Data safety (4.17 privacy guardrail honoured):** the cache layer is
**reference-only** — the only cached values are the education category
vocabulary and symptom-type dictionary keys; **no user-scoped data enters any
shared cache**, and every cache point falls back to the database on failure.
All changes are additive; the two new migrations and the BackgroundJob table
are the only schema deltas (deploy runs `migrate`); Postgres is untouched by
every run.
