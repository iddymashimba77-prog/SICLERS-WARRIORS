## 1. The Session Blocker and How It Was Fixed

Audit (two parallel explore passes — Flutter data layer + backend API surface)
surfaced a hard prerequisite: **there was no app-wide session anywhere.**

- `main.dart` was 7 lines (`runApp`). `app.dart` built routes with null-arg
  constructors. `LoginPage` navigated into the shell via
  `Navigator.pushReplacementNamed(... MainShell.routeName)`, which **discarded the
  controller it just logged in with**.
- `AuthController` is a `ChangeNotifier` (status, `accessToken`, `refreshToken`,
  `email`, `roles`, `restoreSession`, `login`, `logout`, `refreshSession`).
  Pages built their own controllers against per-instance `EphemeralTokenStore`s,
  so tokens never survived navigation and genuine data could never render on Home
  (or inside the shell tabs).

**Fix — `SessionScope`** (`lib/features/auth/presentation/widgets/session_scope.dart`),
a small `InheritedNotifier<AuthController>`:

- Created once in `SicklersWarriorsApp` (`app.dart`, now a `StatefulWidget`) and
  wraps the whole `MaterialApp` → one controller per app instance.
- `LoginPage` reuses `SessionScope.maybeOf(context)` (when no explicit controller
  is injected) so the tokens it just exchanged survive the switch into the shell.
- `SessionScope.controllerOf(context)` gives every screen the shared controller,
  with a private, **unauthenticated fallback** when a widget test pumps a page
  without a scope — signed-out empty states still render and no network is touched.
- No new dependency: this uses only `InheritedNotifier` from the Flutter SDK.

The same fallback was applied to the shell surfaces that already guarded behind
`authController?.accessToken` (`HealthDashboardPage`, `ProfilePage`,
`EducationPage`, `NotificationsPage`, `MedicationPage`, `BloodDonationPage`,
`CommunityPage`, `DonationsPage`, `ConversationListPage`, `EmergencyPage`,
`MedicalProfilePage`) so every hub reached from the dashboard is session-aware.
`AuthController` additionally exposes `firstName` / `lastName` / `displayName`
(parsed from `/auth/me`'s identity subset) and a `refreshIdentity()` helper.

## 2. Data Layer — one aggregator, no new API clients

`lib/features/home/data/home_dashboard_loader.dart` composes the approved
repositories (never re-implements endpoints):

| Slot | Repository call | Path (per existing clients) |
|---|---|---|
| Health/medication/pain/timeline snapshot | `HealthRepository.fetchDashboard` | `GET /patients/me/dashboard/` |
| Personalized identity | `AuthRepository.me` | `GET /auth/me/` |
| Notification badge | `NotificationsRepository.unreadCount` | `GET /notifications/unread-count/` |
| Education recommendation | `EducationRepository.listContent` | `GET /education/content/?page_size=3` |
| Emergency alert | `EmergencyRepository.listRequests` (filter `isActive`) | `GET /emergency/requests/` |
| Blood alert | `BloodRepository.listRequests` (filter `isOpen`) | `GET /blood/requests/` |

- The primary dashboard fetch runs with the light side reads in **parallel**
  (`Future.wait`), each wrapped in its own guard: a failing side call never downs
  the dashboard.
- Transport failures (`http.ClientException` / `TimeoutException`) set an
  `offline` flag so the UI can show an honest offline banner instead of cached or
  fabricated figures. Auth/HTTP errors degrade each slot to an empty state.

## 3. Home Dashboard (`home_page.dart` rewritten)

The full FRONTEND-2 section map, all under the FRONTEND-1 components:

| FRONTEND-2 section | Implementation | Data source / honest fallback |
|---|---|---|
| Personalized header | `AppHomeHeader` — greeting + real name (`/auth/me` → login fallback) + unread notification badge + avatar | real; falls back to email-local-part, never hardcoded names |
| Daily check-in | `_CheckInCard` — user-reported **symptom log** (opens approved `SymptomFormPage`; refreshes on save) | real; "No data recorded yet." when none — no diagnosis wording |
| Quick actions (Tiba/Daktari/Changia/Wasifu entry points) | `QuickActionsGrid` → Medication, Health (Tiba), Daktari hub, Blood, Changia, Wasifu, Medical Profile, Education | valid shell/hub routes |
| Health snapshot | `StatGrid` — active meds, doses today (taken/expected), adherence 7d, symptoms recorded | real dashboard counts; `--` when adherence missing |
| Medication card | `_MedicationsCard` — active list + pending doses, "Add medication" empty CTA | real or `noMedications` |
| Pain & symptoms | `_PainSymptomsCard` — latest symptoms, pain-warning icon at ≥7/10, log CTA | real or `noSymptoms` |
| Emergency / blood alert | `_AlertsCard` — **red `EmergencyCard` only for a real active emergency**; amber `AlertCard` for an open blood request; calm "all clear" otherwise | `EmergencyRequest.isActive` / `BloodRequest.isOpen` filters |
| SOS | global shell FAB (unchanged — no second SOS system) + emergency alert card links to tracking | existing flow |
| Upcoming appointment | `_AppointmentCard` — honest empty state + "Daktari" CTA (no appointment API exists; nothing fabricated) | fixed honest message |
| Health trend | `ProgressCard` adherence + "View health insights" → Tiba | real adherence or `--`/empty |
| Education recommendation | `_LearnCard` — first published article (title/category/author) + library entry | real published content or `noEducationContent` |
| Recent activity | `_ActivityCard` — latest timeline entries | real or `noRecentActivity` |
| Notifications | header unread badge + link into inbox | real `unreadCount` |

Responsive: single column on phones, 2 columns tablets, 3 on desktop, 4 on large
desktop (`_AdaptiveGrid`); full-width hero sections (header, offline banner,
check-in, quick actions, alerts, snapshot, trend) above the grid. Loading uses the
calm `SkeletonCard`; failure uses `ErrorRetryView` with pull-to-refresh
(`RefreshIndicator` + `AlwaysScrollableScrollPhysics`) everywhere.

**Safety rule honoured throughout:** no fake health figures ever render — every
slot shows a real value or an explicit "No data recorded yet."‑style empty state,
and offscreen emergency copy never implies a diagnosis.
