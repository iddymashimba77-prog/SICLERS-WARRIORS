## 2. NOT FIXED — accepted risks

### SF-022 — AI-trends uid oracle (LOW)
- **Behaviour:** `POST /api/ai/trends/` returns `404` for a non-existent uid
  but `403 consent_unavailable` for an existing user lacking consent.
- **Why NOT FIXED:** a partner change collapsed both to 404 but **broke the
  approved legacy test contract** — `test_cross_patient_trends_requires_consent`
  asserts `403` + an audit row + `code=consent_unavailable` for a real
  cross-patient uid, and the invalid-uid case asserts `404`. The contract that
  passed the review was 403/404 differential; changing it now would regress a
  gated suite for a LOW-severity, design-mandated signal.
- **Compensation:** uids are 160-bit random UUIDs (unguessable, non-sequential);
  `ai.trends` is rate-limited; denied attempts are audited; the endpoint returns
  no user identity in either branch.
- Carry-over: decide as a future P0/P1 re-roll with a formal test-contract
  change (Stage 5 / change-request).

### SF-023 — Audit append-only is ORM-layer only (MEDIUM)
- **Why NOT FIXED:** a DB trigger/`SELECT ... FOR NO UPDATE`-style role grant on
  `audit_logs` requires a **production deployment of DB grants** (the trigger
  would also need a migration authored against Postgres). The application layer
  ships with zero update/delete paths for audit rows (`AuditLog` has only
  create/read callers), which the 337-test suite exercises.
- **Compensation:** documented in `security-risk-register.md` §4 (control gap);
  the DB-level `NO UPDATE/DELETE` grant is added to the production provisioning
  runbook at deploy time (not silently skipped — tracked in §4 below).

## 3. NOT APPLICABLE / NOT AVAILABLE — why

- **SF-024/025/026/027** are **NOT APPLICABLE**: non-security or
  operational/dev-only surfaces, explicitly outside the hardening scope,
  recorded for transparency rather than silently dropped.
- **SF-028** is **NOT APPLICABLE** to the backend hardening stage: it touches
  the Flutter client storage path; the platform-secure storage decision lives in
  the mobile stage (the app already stores the JWT via the in-memory token store
  by design for the autofill/dev flow).
- **SF-029/SF-030** are **NOT AVAILABLE**: the tools (`pip-audit`, `safety`,
  `trivy`) and the mechanism (TOTP codes) are absent. For each, the compensating
  control is stated and the gap is tracked (4.16 MFA boundary + §4 below).
