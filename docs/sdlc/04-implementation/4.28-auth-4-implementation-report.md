## 1. Audit Charter

AUTH-4 answers four questions over the hardened admin surface:

1. **Does the session advertise only what the grants table allows?** — `/me`
   must be the single authoritative RBAC projection, identical to what the
   portal renders from.
2. **Can a non-privileged actor reach any admin surface?** — replay every admin
   read/write endpoint as PATIENT and anon; only 403/401 may come back, and the
   denial must land *before* resource resolution (no existence oracle).
3. **Is governance recorded?** — privileged decisions must emit audit rows;
   denied lateral attempts must not mint `admin.*` decision rows.
4. **Do the session hardening controls hold?** — admin refresh TTL (8h) vs
   patient (24h), TTL preserved across rotation, MFA step-up boundary.

## 2. `/me` RBAC Contract (Session & Permission Advertisement)

`accounts/serializers.py.UserSummarySerializer` advertises `role_codes` +
`permission_codes` computed from live role grants minus DENY overrides.
`accounts/tests_auth4_audit.MeRbacContractTests` pins the server side of the
contract the mobile portal consumes:

- **SUPER_ADMIN** — `role_codes` includes SUPER_ADMIN; `permission_codes` ⊇ the
  RBAC kernel (`admin.permissions.manage`, `admin.roles.manage`,
  `admin.users.manage`, `admin.audit.read`, `admin.audit.export`).
- **ADMIN** — exactly `["ADMIN"]`; holds the read matrix and `admin.audit.read`
  but **never** the SUP-only writes (`admin.permissions.manage`,
  `admin.audit.export`).
- **PATIENT** — exactly `["PATIENT"]`; holds feature codes (`doctors.view`,
  `blood.donate`, medication/health codes) but **zero** ADMIN-3 portal codes —
  verified as a disjoint intersection with the mobile `AdminPermissions` set.
- **Anonymous** — `/api/auth/me/` → `401`.

This is the guarantee `adminSectionsFor(session.permissions, session.roles)`
relies on (§4.27 §5): the portal can only render what the server grants.

## 3. Privilege-Escalation Denial Sweep (Attack Simulation)

`AdminSurfaceDenialSweepTests` replays the entire admin catalog as a PATIENT and
as an anonymous caller:

- **16 read endpoints** (`/admin/users|security-events|roles|audit-logs|dashboard|
  analytics|ai/monitoring|financial/summary|donations|campaigns|campaigns/
  verification-queue|facilities|doctors/verification-queue|education/content|
  community/reports`, `/blood/requests/verification-queue`): all → **403** for
  the patient, **401** for anon.
- **17 write endpoints** (activate/deactivate/role grant/revoke, role-permission
  write, doctor verify/suspend, facility verify, blood verify/reject, campaign
  verify/pause/close, refund, content review, report resolve, broadcast):
  all → **403/401**. Fabricated UUIDs are used on purpose — the 403 must be
  returned by the permission layer *before* the lookup, so a crafted id can never
  leak resource existence via a 404 (only the true facility route, which has no
  trailing slash, is probed at its real path).
- **Audit-noise discipline** — after the full sweep `AuditLog` count is
  byte-for-byte unchanged: denials fail silently and record nothing; only
  successful decisions mint `admin.*` rows.

## 4. Audit-Event Coverage

Governance is continuously recorded for every **successful** privileged decision
(verified across `tests_admin_roles.py`, `facilities/tests.py`,
`donations/tests.py`/`tests_admin.py`, `audit/tests_admin.py`):

- Role grant/revoke → `admin.user.role_grant` / `admin.user.role_revoke`
- Permission grant/revoke → `admin.roles.permission_grant` / `.permission_revoke`
- Activate/deactivate → `admin.user.activate` / `admin.user.deactivate`
- Facility verify, campaign verify/pause/close, doctor verify/suspend, blood
  request verify/reject, refund, broadcast, audit export — each with its action
  code + resource + reason.
- The export appends its **own** audit row and is SUPER_ADMIN + reason-gated;
  no list/export serializer leaks free-form `details` (`test_rows_never_include_payload`,
  `test_export_never_includes_details`).

## 5. Session Hardening Review

- **Shorter admin session** — login/refresh TTL for ADMIN is 8h (±) vs 24h for
  PATIENT; TTL is **preserved across refresh rotation** (ready-existing
  `AdminSessionTtlTests`, re-confirmed by the full-suite run).
- **MFA step-up boundary** — an `mfa_enabled` SUPER_ADMIN is refused on the whole
  admin surface with a recorded `MFA_CHALLENGE` security event, including
  read-only surfaces; a non-admin `mfa_enabled` user is unaffected on general
  surfaces (`AdminMfaBoundaryTests`).
- **Account status** — `IsAuthenticatedRespectStatus` gates every protected view;
  suspended/deactivated identities cannot obtain productive access.
- **C17 boundaries** — self role-change denied; ADMIN cannot assign privileged
  roles or touch privileged accounts; the SUPER_ADMIN kernel is lockout-guarded
  (`tests_admin_roles.py`).

## 6. Cross-Surface Denial Consistency

The sweep surfaced one **consistency observation** (not a gap): the facility
verify route is registered **without** a trailing slash while every other admin
route uses one — so a probe of `/verify/` gets a resolver 404 while `/verify`
gets the correct 403. The mobile repository deliberately uses the raw
no-slash URI (§4.27 §6) and this asymmetry is documented in the mobile contract
comment; the AUTH-4 probe targets the real route so the discrimination
assertion (403, no existence oracle) holds where it counts.

## 8. Findings & Confirmations

- **Confirmed:** permission-first enforcement across the admin catalog — a
  caller is denied before any object lookup, so fabricated ids cannot be used to
  fingerprint the API (every sweep endpoint returned 403/401, never a data row).
- **Confirmed:** `/me` is the single authoritative RBAC projection and matches
  the mobile portal's permission set exactly.
- **Confirmed:** denied attempts are audit-silent; every approved privileged
  decision is audited with a human reason.
- **Confirmed:** admin session TTL + MFA step-up + C17 role boundaries hold
  under rotation.
- **Finding (resolved in the audit test, not in product code):** AUTH-4's own
  first cut swept the facility route with a trailing slash (resolver 404) and
  used a too-broad code-prefix check that flagged the benign feature code
  `doctors.view`. Both were corrected to target the real route and the exact
  portal-code set — the product code was already correct.

## 9. Remaining Issues & Caveats

- The audit covers the **authorization** surface. Password/token cryptology,
  throttling tuning and provider-side payment verification are covered by their
  own stages (AUTH-1, §4.13/4.15 health, donations we/§4.16) and are outside this
  audit's charter.
- MFA is **step-up only**: the flow denies the admin surface for
  `mfa_enabled` accounts (TOTP enrollment/unlock is a documented pending item);
  the boundary is asserted, not the challenge round-trip.
- The no-trailing-slash facility route remains the one asymmetric contract point
  (see §6); it is pinned on both sides by tests.
