## 1. Scope

Deliver the curated education surface defined by the approved design: a **flat,
two-level model** — `education_categories` (1) → `educational_content` (N) —
with a submit-then-review publishing workflow (C12). No courses, lessons,
quizzes, certificates, video/attachment pipelines or premium access exist in
any approved requirement or design document; none were invented (see §7).

- **Backend:** new `education` app (models, serializers, services, permissions,
  throttles, views, admin, seed migrations).
- **Flutter:** the `/education` library (categories + search), content detail
  with a "not medical advice" banner, and session-local bookmarks; entries added
  on Home and in the Community page.

The design's legacy `/api/v1` prefix is not used; the monorepo convention
`/api/` (no version namespace) is followed, as in 4.10.

### 2.1 Approval & permissions (role-permission matrix §3.16, C12)

| Code | Roles |
|---|---|
| `education.view` | all 12 roles (A) |
| `education.publish` | SUPER_ADMIN/ADMIN (A); DOCTOR, ORGANIZATION (C12 — DRAFT only) |
| `education.review` | SUPER_ADMIN/ADMIN |

C12 is honoured end to end: a DOCTOR/ORGANIZATION-authored piece lands as DRAFT
(secured at the DB layer too), is not visible to any other user, and only
becomes PUBLISHED after a SUP/ADM review acting on `education.review`.

### 2.2 Endpoints (approved api-design §20 / matrix §18)

- `GET /api/education/categories/` — public, ordered.
- `GET /api/education/content/` — public, **published only**; `q` (and the
  `search` alias, the two design docs disagree) filters title/body; `category`
  filters by code; `author=me` not exposed on the public list.
- `GET /api/education/content/{uid}/` — published only; 404 for drafts to
  non-authors; author reads own draft.
- `POST /api/education/content/` — `education.publish`; creates DRAFT.
- `PATCH/DELETE /api/education/content/{uid}/` — author only; editable while
  `DRAFT/REJECTED/ARCHIVED`; DELETE is DRAFT-only (never destroys a live/ever-
  visible article).
- `POST /api/education/content/{uid}/submit/` — author only; →IN_REVIEW.
- `GET /api/admin/education/content/` — `education.review`; all statuses,
  `?status=` filter.
- `POST /api/admin/education/content/{uid}/review/` — `education.review`;
  `{decision: approve|reject, reason}`; only `IN_REVIEW`; approve → PUBLISHED,
  reject requires reason → REJECTED.

Audit codes: `education.content.create|update|delete|submit|review`.

## 4. Security review

- **Data boundary:** the public surface returns only publication metadata;
  reviewer identity, `rejection_reason` and workflow internals are admin-only.
  Author projection is `uid` + `display_name` (no email/phone/PHI). Gate
  verifies `author` keys == `{'uid','display_name'}` and no `rejection_reason`.
- **Draft confidentiality:** drafts are invisible/404 to every non-author token
  (and anonymous). `data-classification-security.md`: drafts internal, published
  public.
- **C12 enforced server-side:** `education.publish` for DOC/ORG yields locked
  DRAFT; only `education.review` (SUP/ADM) publishes. Non-reviewer trying the
  admin endpoint → 403; reviewing a non-`IN_REVIEW` article → 400.
- **Sanitisation:** title/body/cover/reason through the community allow-list
  HTML sanitizer on write (security checklist "REQUIRED — allow-list tags").
- **Abuse controls:** writes/submits 30/min, review 60/hour (§29).
- **Integrity:** published/archived content can never be hard-deleted; archived
  is terminal; no `published_at` until a review approves. Every workflow
  mutation is audit-logged with the action code only.

## 6. Documented decisions / discrepancies (no silent divergence)

1. **Flat model, no Warrior Academy hierarchy.** The approved SSoTs (database-
   design §17, ERD, api-design §20, matrix §18) define only categories + content.
   The "Warrior Academy" *name* (from earlier 3.x review decks) is used only as
   a marketing label in this document title; no course/lesson/quiz objects were
   created, and feature-gated/premium education is explicitly future-stage.
2. **Category codes.** The design names six topics; stable machine codes
   (`SICKLE_BASICS`, `CRISIS_PREVENTION`, `NUTRITION`, `EXERCISE`,
   `CAREERS_FAMILY`, `LIVING_WELL`) were chosen for the API `category` filter.
3. **Search param alias.** api-design §20 and matrix §18 disagree (`q` vs
   `search`); both are accepted and documented.
4. **Title is required on create** (matrix shows the field without constraint);
   body is required and non-empty.
5. **Bookmarks are local only (EDU-005).** No bookmark table/endpoint exists in
   the approved schema; the Flutter store is session-local and lost on restart,
   and does not cover "reading progress" (deferred).
6. **No legal add-path to PUBLISHED.** Content reaches PUBLISHED only through a
   SUP/ADM approval; an author can never self-publish.
7. **No education notifications.** The approved `Notification.TYPE` set has no
   education event; none were invented — the workflow remains pull-driven.
8. **`cover_url` accepted as a bare http(s) URL** for schema completeness per
   the design row, but there is no upload/media pipeline yet (as 4.10's ASG-6).
