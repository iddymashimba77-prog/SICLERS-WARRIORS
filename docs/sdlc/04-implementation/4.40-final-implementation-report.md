## 2. Objectives & scope

The directive asked for a global-system integration pass: a device theme
(Light/Dark/System) and language (English/Kiswahili) system on mobile, an
appearance system on admin web, verified public-page flows, news & ticker
publishing, dynamic branding driven by the backend, admin-backend integration,
tightened error handling, and a full user-flow audit — all verified end-to-end.

## 3. Global architecture (what talks to what)

```
Postgres ── Django API (581 tests) ──┬─ Flutter mobile app        (174 tests; theme/l10n/prefs/tokens/branding)
                                     ├─ React admin web          (typecheck+build clean; theme provider; live KPIs)
                                     └─ Public/site endpoints    (news/ticker/branding, AllowAny, published/active only)
```

Device settings are split by ownership: **session tokens** (`sw.auth.*`) and
**device theme/language** (`sw.app.*`) live on the device (shared_preferences);
the **brand** and **content** come from the backend (server of truth); admin
web appearance (`sw.admin.theme`) persists in localStorage.

## 4. Theme system — Flutter mobile

- `AppPreferences` (shared_preferences) stores `sw.app.theme_mode`
  (`system|light|dark`), default `system`.
- `ThemeController extends ValueNotifier<ThemeMode>`; `ThemeScope`
  (InheritedNotifier) rebuilds every theme-consuming surface; `MaterialApp`
  drives `themeMode` from its value.
- Setting surface: Profile → Preferences → Appearance
  (`SettingsSheet` Light/Dark/System), persisted per device, survives logout
  and restarts.
- Tested: default system, persist dark/light, no-op guard, reload re-seed.

## 5. Theme system — Admin Web (React)

- `src/lib/theme.tsx` — `ThemeProvider` + `useTheme`; mode
  `light|dark|system` stored in `localStorage['sw.admin.theme']`, applied via
  `document.documentElement.dataset.theme` *before first paint* (no flash).
- `index.css` re-resolves every `--sw-*` token under `[data-theme='dark']`;
  navy sidebars/avatar/buttons re-pinned to the fixed dark base so the
  re-themed heading color cannot white-out them. `color-scheme` set so native
  inputs/scrollbars follow.
- Toggles: Settings → Appearance (Light/Dark/System segment chips, System shows
  the resolved device value) and a 🌙/☀️ quick toggle in the shell top bar.
- Verified: `tsc -b` + `vite build` clean; dev server serves the new tokens.

## 6. Language system (English / Kiswahili) + l10n infrastructure

- `AppLocalizations` (`lib/core/l10n/`) — dependency-free EN/SW dictionaries
  (synced key sets, script-checked), `tr(key)` with EN fallback then the key.
  Material/Widgets/Cupertino delegates supplied so pickers/dialogs translate.
- `LocaleController` — `null` = **follow device** (default), `en`/`sw`
  persisted under `sw.app.locale`; invalid tags degrade to follow-device.
  Standalone (delegate-less) contexts fall back to **Swahili**, matching the
  brand's Kiswahili-first surfaces.
- Switched chrome: public home hero/sections/mega-menu/footer, shell nav labels
  (Nyumbani/Daktari/Tiba/Changia/Wasifu — pinned to the existing app-string
  contract), login form/validation/buttons, profile page, settings sheet, SOS
  tooltip.
- Tests assert every key resolves non-empty in both locales and the flagship
  labels/wordings.

## 7. Session persistence

- `SharedPrefsTokenStore implements TokenStore` — JWT pair under
  `sw.auth.access`/`sw.auth.refresh`, sign-out clears only these keys.
- Plugin-round-trips are guarded with an 800 ms timeout so a hung platform
  channel degrades to in-memory (tests/exotic platforms) instead of hanging the
  splash behind restore; covered by unit tests with mock initial values.

## 8. Public page flows & routing guard

- Flutter CTAs now route through `AppRouter.goTo()`: anonymous users hitting a
  protected surface (`/shell`, `/admin*`, medical/profile/etc.) go to
  `/login`; public surfaces stay open. Dead link `/health/timeline` →
  `/health` fixed.
- Verified flows: public home → login → MainShell (role-aware) and the
  "rejected login stays with an error / successful login replaces with the
  shell" contract in the navigation suite.

## 9. News publishing flow

Create (DRAFT) → publish/unpublish/archive/feature (admin) → public feed +
detail + latest (published only). Non-UUID detail reads (`not-a-real-uuid`,
`123`) now return the standard `404 NOT_FOUND` envelope instead of a 500 —
fixed in `content/views.py` with a shared `_by_uid()` guard applied to the
public detail and both admin CMS `get_object`s; regression-tested for public
and admin (news + ticker) surfaces.

## 10. Ticker publishing flow

Admin CMS create/activate/deactivate + public `GET /api/content/ticker/` with
time/priority effectiveness filtering. Added the missing `retrieve` on
`AdminTickerViewSet` so `GET /api/admin/content/ticker/{uid}/` matches the
documented contract and malformed uids 404 rather than 405/500.

## 11. Dynamic branding

- Backend `GET /api/branding/` → `{logo_url, logo_alt, has_logo}` (live:
  `has_logo: true`); admin console is the single edit point.
- Flutter `BrandingController` fetches once per launch (silent on failure),
  resolves server-relative logo URLs against the API origin
  (`/api/branding/logo/` → absolute), and `AppLogo` prefers the live bytes with
  bundled + typographic fallbacks. Parsing/failure tests included.
- Admin web renders the same backend logo via its brand context.

## 12. Admin-backend integration (live data, not stubs)

- Root cause of sparse dashboard KPIs: the analytics snapshot job had never run
  against real data. Executed `sync_analytics_snapshots --days 30` → **184
  rows**; live `GET /api/admin/dashboard/` now returns populated KPI cards
  (users, blood requests, emergencies, …) and 30-day trends.
- Admin web builds type-clean against this payload contract.

## 13. Error handling

- One envelope everywhere: `{"error":{"code","message","details",
  "correlation_id"}}`. Added `502 → BAD_GATEWAY` to the status→code map
  (`core/handlers.py`) alongside the existing 400/401/403/404/409/429/500/503.
- Malformed uid reads that previously escaped as 500s now fold into `NOT_FOUND`.
- Unit tests pin every code (including `BAD_GATEWAY`) and the generic
  `API_ERROR` fallback.

## 14. User-flow audit findings & fixes

1. News detail 500 on non-UUID → 404 (public + both admin CMS readers).
2. Admin ticker GET detail absent (405) → implemented + malformed uid 404.
3. Language default resolved to English even when "follow system" was intent →
   seeded `null` and made the fallback Swahili; unsupported tags now degrade to
   follow-device.
4. Boot could hang behind the splash when the prefs plugin channel hangs →
   800 ms timeout fallbacks in prefs load and token store.
5. `tagToLocale('')` could produce an empty language code → empty string now
   falls back to the default tag.
6. Dead public-home link (`/health/timeline`) → `/health`.
7. Mobile shell labels localized to `AppLocalizations` keys while keeping the
   exact strings the navigation contract asserts.

## 21. Security considerations

- Tokens never source-controlled; persisted on-device only, cleared separately
  from device prefs at sign-out. Plugin timeouts prevent hang-based DoS of boot.
- Error envelope exposes safe messages only; 500s keep the generic copy.
- No secrets in `AppConfig` (API origin only); no PHI in test fixtures.
- Admin web theme preference is device-local (no account surface); no new
  privilege/endpoint surface added.

## 22. Data safety & ethics

Established discipline held: no DROP/reset, no migration deletion, no fake
rows. The single live write is the analytics snapshot job, executed against the
real database with real aggregates — self-consistent and reproducible.
