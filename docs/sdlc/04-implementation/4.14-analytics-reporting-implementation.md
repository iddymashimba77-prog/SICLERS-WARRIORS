## 1. Scope

Deliver the approved analytics surface **backend-only**: an idempotent
`analytics_snapshots` aggregate store (§19), a **role-adaptive KPI dashboard**
(SUP/ADM full kernel, VO C6 verification kernel; admin-web §5), a **whitelisted
reporting endpoint** with granularity rollup + date windows (api-design §23), and a
**C4-gated, audited CSV export** (admin-web §28). Two explicit rules shaped scope:

1. **Aggregates only (AD-7).** Every stored value is a count/sum/average over a
   population. No identifiers, notes, contact details or medical payloads ever
   reach `analytics_snapshots` or any response/export — `dimensions` carry
   categorical slices only (status, urgency, severity, category, code).
2. **No unapproved surfaces.** `/ai/trends/{patient_uid}` (AD-2 placeholder),
   the generic report-export gap endpoint (`POST /admin/exports`), insight
   engine/ML, geographic analytics, DOCTOR/CAREGIVER health-trends delivery
   (consent unmodelled — ODD-8), and the mobile admin analytics feature
   (hidden Mobile Admin) are all **NOT implemented** and are logged in §7/§8.

### 2.4 DBD-2 backfill stance (state metrics)

`state` metrics replay history with **latest-known statuses** (there is no audit
timeline for every status transition in the domain tables); this matches the
design's stored-snapshots choice and is recorded here for the DBD-2 review.
`delta` metrics are exact in-window event counts — safe to rebuild any day.

## 4. Security review

- **Aggregate-only.** The controller never materialises a raw domain row; every
  figure comes from `analytics_snapshots` or a pure `Count/Sum/Avg`. CSV columns
  are exactly the snapshot fields; tests assert no PHI column name appears.
- **Deny by default.** 5 of 12 roles have `analytics.view`; every denied
  authenticated attempt is audited `DENIED` (audit never stores request bodies).
- **C6 scope.** A VO's metric set is whitelisted server-side; requesting a known
  metric outside the scope is 403 (audited), an unknown metric is 400.
- **C4 export.** ADMIN exports require a `reason`; every export logs format,
  filters, `row_count` and reason. No generic `POST /admin/exports` gap endpoint
  was built (not approved).
- **Bounded windows.** Max 366-day window per request keeps reporting reads cheap
  (NFR-PERF-002); 60/min throttle bounds abuse; suspended accounts 403.
- **Idempotent aggregation.** Unique (metric, dimensions, granularity, measured_at)
  + Python-side exact-key matching — re-running the job upserts, never duplicates.

## 6. Documented decisions / discrepancies (no silent divergence)

1. **Exact JSON key matching in Python, not `update_or_create`.** Django's
   JSONField `filter(dimensions=…)` is containment, not equality, and an empty
   `{}` predicates true over any jsonb object on Postgres — both would corrupt
   the §19 unique key. Exact matching is done against the canonical dict after a
   narrow DB pre-filter; volumes per (metric, day) are tiny, so this stays cheap.
2. **Role kernel over one shared dashboard.** admin-web §5 flags a GAP — the
   KPI set is role-adaptive (SUP/ADM full, VO verification). The flag is honoured:
   one endpoint, kernels selected server-side, and the section's line-130 note is
   documented exactly as a gap, not silently "fixed".
3. **WEEKLY/MONTHLY are sum-rollups** of stored DAILY rows (**avg-of-averages is
   rejected** — `symptoms.avg_pain` at WEEKLY/MONTHLY → 400). Keeps the store
   granularity honest with §19.
4. **`analytics.health_trends` is seeded but endpoint-less.** Granting rows exist
   (SUP/ADM C4, PATIENT A) so the permission model is real and testable, but the
   `/ai/trends/{uid}` endpoint is an AD-2 placeholder — see §8.
5. **CSV triggered by `export=csv`, not `?format=csv`.** The project renders a
   single JSON envelope (`ApiEnvelopeRenderer`) and does not register a global CSV
   renderer; a dedicated `export` switch keeps the renderer contract stable while
   still satisfying admin-web §28 behavior (filters + reason + row_count audit).
6. **Audit rows for denied access are count-light by design** — one `DENIED` row
   per denied authenticated attempt with no PHI, matching the existing
   `access_denied` conventions elsewhere in the codebase.
