## 1. Scope & Charter

CONTENT-1 answers three questions:

1. **Can editors create and manage public content without touching backend code
   or the shell?** — a `content` app whose lifecycle rules are enforced by the
   server and surfaced through a dedicated admin portal section.
2. **Does the public site render that content under the official brand?** — a
   rebuilt public home (logo lockup, header mega-menus, hero, news sections,
   cycling ticker) plus branded auth screens.
3. **Does the content surface hold the same security bar as the rest of the
   platform?** — least-privilege permission codes, throttle limits, upload
   hardening, and silent-denial auditing already verified by AUTH-4.

## 2. Backend `content` App

New Django app mounted at `backend/content/` and registered in
`config/settings/base.py` + `config/urls.py` (`path("api/", include("content.urls"))`).

### Models (`models.py`)

- **`NewsArticle`** — `uid` (uuid), `title`, `category` from `NEWS_CATEGORIES`
  (HEALTH, BLOOD, COMMUNITY, EDUCATION, EVENTS, ANNOUNCEMENTS, FUNDRAISING),
  `excerpt`, `body`, `cover_image`, `cover_alt`, `tags`, `featured`, `status`
  (DRAFT/PUBLISHED/ARCHIVED), `published_at`, `author` FK. Indexes on
  `(status, published_at)`.
- **`TickerAnnouncement`** — `uid`, `message`, `announcement_type`,
  `link_url`, `is_active`, `priority`, `start_at`/`end_at` (optional window);
  `is_effective(now)` gates visibility by status + time window.
- Migrations **`0001_initial`** + **`0002_seed_content_permissions`** (the two
  `content.*` codes are seeded, not hand-inserted).

### Permissions & Governance

- New codes **`content.news.manage`** and **`content.ticker.manage`** are
  granted to SUPER_ADMIN + ADMIN **only** (never MODERATOR/PATIENT) via the
  existing RBAC grants machinery; the portal render + the denial sweep both pin
  this.
- Every successful admin mutation records an audit row (`news create/update/
  publish/unpublish/archive/feature/cover`, `ticker create/update/activate/
  deactivate/delete`); denied calls stay audit-silent, matching AUTH-4's
  discipline.

### Throttles & Upload Hardening

- `content/throttles.py` — `ContentWriteThrottle` (30/min, user-scoped) and
  `ContentCoverThrottle` (10/min) guard the admin catalog; public endpoints sit
  under the platform-wide defaults (`anon` 100/min, `user` 200/min).
- `content/upload_validation.py` probes + re-encodes uploads with **Pillow**:
  only PNG/JPEG/WebP, 5 MB cap, re-encoded to a fresh in-memory image before
  abs-save — a malicious "image" can never be persisted verbatim.

### Serializers

- `NewsCategorySerializer` (public taxonomy).
- `PublicNewsSummarySerializer` (list/feed: no body) and
  `PublicNewsDetailSerializer` (full body + public author display).
- `AdminNewsWriteSerializer` / `AdminNewsUpdateSerializer` — `status` is
  read-only on writes (`_clean_status`), unpublish/archive are explicit actions;
  `validate_excerpt` derives a default excerpt from body whenever blank
  (reads `self.initial_data or {}` — `self.initial` is `None` during field-level
  validation, see §6 finding).
- `PublicTickerSerializer` (`is_effective` gate) and `AdminTickerSerializer`/
  `AdminTickerUpdateSerializer`.

### Services & Lifecycle (`services.py`)

- `publish_news` — DRAFT **or ARCHIVED** → PUBLISHED (publish = publish,
  republish = news revived); raises only when already PUBLISHED; sets
  `published_at = timezone.now()` and `featured = False` on publish.
- `unpublish_news` — PUBLISHED → DRAFT, clears `published_at` + `featured`.
- `archive_news` — DRAFT/PUBLISHED → ARCHIVED.
- `feature_news` — PUBLISHED only, single featured; toggling featured first
  clears the previous featured row.
- Editing (serializer) is allowed on DRAFT/ARCHIVED; delete only on DRAFT
  (server-enforced; the UI hides invalid controls accordingly).

### Views & URLs

- Public: `GET /api/content/news/` (paginated, `q`/`category`/`featured`
  filters), `GET /api/content/news/latest/` (hero), `GET /api/content/news/
  categories/`, `GET /api/content/news/{uid}/`, `GET /api/content/ticker/`
  (active + time-effective, priority-sorted) — all `AllowAny` and serving only
  PUBLISHED/active rows.
- Admin (`content.news.manage` / `content.ticker.manage`): full CRUD +
  `POST .../{uid}/publish|unpublish|archive|feature/`, `POST .../{uid}/cover/`
  (multipart), `POST .../{uid}/activate|deactivate/`.
- **`get_parsers` always returns `[MultiPartParser(), FormParser(), JSONParser()]`** —
  see §6.

## 6. Findings Resolved

- **`initial` is `None` during field-level serializer validation** → 500 during
  excerpt defaulting; fixed to read `self.initial_data or {}`
  (`content/serializers.py`).
- **415 on multipart cover** — root cause is inside DRF: `ViewSetMixin.
  initialize_request` calls `super()`, which runs `get_parsers()`, **before**
  `self.action` is assigned, so parser selection could never branch on the
  action. `AdminNewsViewSet.get_parsers()` now returns multipart + form + JSON
  for every method (safe: JSON payloads still parse; multipart AcceptedType is
  needed only for cover).
- **`NameError: 'now'`** in `services.publish_news` → explicit
  `from django.utils import timezone` + `timezone.now()`.
- **AUTH-4 sweep false/positive hardening** — facility verify route probed at
  its real (no trailing slash) path; portal-code set asserted exactly (no
  `doctors.view` collision).
- **Mobile bare-list bug found by the new tests** — public ticker/categories
  return a top-level JSON list; `_envelope` previously cast to `Map` and would
  throw a `TypeError` at runtime. Now lists are wrapped into
  `{results: [...]}` so `listTicker`/`listCategories` and the ticker banner
  parse correctly against the real backend.
