## 1. Scope

A hardening pass, not a feature stage. Every change is a defence against a
**specific register/design control** and each is proven end-to-end by the new
`security_hardening` test app and `stage417_gate.py`. Themes:

1. **Session lifecycle (§20).** Logout denylists the refresh; rotation
   denylists the old refresh; **password change and password-reset revoke every
   outstanding session** (denylist + JWT rev-claim); suspension flips
   `is_active` so the live session and rotation pipe stop immediately.
2. **Password policy (§25).** Django AUTH_PASSWORD_VALIDATORS now run at
   **register**, **reset-confirm** and **change-password** — not just via
   `create_user`.
3. **Reset oracle/cooldown (§26).** Requests for unknown accounts still return
   the same success (uniform `202`, never a 500), mint **nothing** (no one-time
   token, no security event), and a per-account cooldown caps token issuance.
4. **Provider fail-closed (§27).** In a `production` payment env the shared/dev
   webhook secret is refused; a **per-provider live secret** is required; the
   production settings module refuses to import without an operator-supplied
   `DJANGO_SECRET_KEY` / payment secrets.
5. **MFA on money movement (§28).** Refund access honours the MFA step-up
   boundary exactly like the other admin mutations from 4.16.
6. **Community privacy (§15).** `moderation_reason` is moderation-only; comment
   threads of HIDDEN posts are 404 for members; reaction types are whitelisted.
7. **Blood PII + chain of custody (§16).** The donor-facing request list is the
   public subset (no requester contact, no rejection internals); a COMPLETED
   donation event requires an ACCEPTED/FULFILLED `BloodMatch`.
8. **Emergency verification (§18).** Clients can no longer self-assert
   `phone_verified` on SOS creation.
9. **Schema/docs gating (§33).** OpenAPI schema + Swagger UI are silent-404 for
   everyone except audit readers while DEBUG is off; open in DEBUG.
10. **Settings fail-closed (§30).** Production refuses placeholder secrets at
   import time (verified with a subprocess import in the gate).

No migration files are produced by the repo code; the one schema-relevant
change is enabling the bundled `rest_framework_simplejwt.token_blacklist` app,
which ships its own two migrations (`blacklistedtoken`, `outstandingtoken`) —
deploy adds `migrate` (never run against dev Postgres; the gate/suite prove the
paths on ephemeral SQLite).

## 2. Backend changes

### 2.1 Accounts / sessions (`backend/accounts`)

| File | Detail |
|---|---|
| `serializers.py` | `_enforce_password_policy` (runs `AUTH_PASSWORD_VALIDATORS` + length rule verbatim on whatever password the entry point accepts); `_revoke_user_tokens(user)` inlines **every** outstanding `RefreshToken` (`outstand()`, not only rotate-on-refresh), minting denylist rows so there is no "non-rotated" escape hatch; `_deliver_reset` now writes `SecurityEvent(event_type="PASSWORD_RESET", result="REQUESTED"...)` with `detail.phase="requested"` + masked code (the previous custom event type is NOT in `SecurityEvent.KINDS`). |
| `serializers.py` | `RegisterSerializer` validates policy before `create_user`; `PasswordResetConfirmSerializer.validate` enforces policy, `save` revokes ALL sessions; `ChangePasswordSerializer` validates policy + revokes all sessions on success; `LogoutSerializer` gained a real `save()` (previously `NotImplementedError` → 500), uses `timezone.UTC` (Django 5 removed `timezone.utc`), and `token.blacklist()` with the previously-missing `TokenDenyList` import (a latent 500); `RefreshRotationSerializer` denylists the presented refresh via `blacklistedtoken`; `token_pair_for` now calls `refresh.outstand()` so login/register-issued refreshes are recorded and revocable. |
| `throttles.py` | `AuthThrottle` (`scope="auth"`, hashed identifier when authenticated → stable key per user, IP fallback) wired to the auth endpoints to hold brute-force/400-spam behaviour in one place; production rate `10/minute`, dev/test effectively unlimited. |
| `views.py` | `AuthThrottle` attached to Register, Login, Logout, Refresh, PasswordResetRequest, PasswordResetConfirm. `ChangePasswordView` intentionally keeps DRF's default user throttle. |
| `admin_views.py` | Deactivate now also sets `is_active=False` (persisted in `update_fields`) — the existing test suite only asserted `account_status`, so it stays green, and the live-session kill is now real. |

## 4. Security review

- **Auth throttle** centralises brute-force budget on the auth scope (10/min
  prod) with a stable hashed identifier; test settings raise it so the 337-test
  suite never 429s itself.
- **Revocation is complete, not best-effort.** `token_pair_for` `outstand()` +
  `_revoke_user_tokens` blacklister mean the "login-issue-then-hope-refresh-is-recorded"
  gap (previously refresh only got denylisted once rotated) is closed.
- **Logout/rotation genuinely 500-proof.** `LogoutSerializer.save()` existed,
  `TokenDenyList` import existed, `timezone.UTC` (Django 5) — the unit suite
  covered the happy path; those two were latent 500s on the real path.
- **MFA boundary covers money.** DonationRefundAccess now matches every other
  4.16 admin surface (`MfaPolicy`), so mfa_enabled admins are step-up blocked
  there too.
- **No moderation internals leak.** Hidden threads are 404 (silent), reaction
  types are an allow-list, moderation_reason is permission-gated.
- **Schema is not world-readable.** OpenAPI/Swagger were discoverable by anyone;
  now audit-readers only (silent 404), open in DEBUG per convention.
- **Settings fail closed.** Production cannot boot with the committed
  placeholder SECRET_KEY or the dev webhook secret — verified by a real
  subprocess import in the gate.

## 6. Documented decisions / discrepancies (no silent divergence)

1. **`token_blacklist` is a schema change.** Two tables ship with the package's
   own migrations; `makemigrations --check` stays clean because none are
   repo-made. **Deploy folder must run `migrate`** once. Not run here (ephemeral
   SQLite only; dev Postgres untouched) — see the findings report.
2. **AI-trends uid oracle is NOT FIXED (accepted risk).** A partner attempt to
   collapse the differential (invalid uid → 404, existing-but-denied user →
   403 consent_unavailable) **broke the approved test contract**
   (`test_cross_patient_trends_requires_consent` = 403 + audit +
   `consent_unavailable`; `invalid uid` = 404) and was reverted. Compensation:
   uids are 160-bit random UUIDs, `ai.trends` is rate-limited region-wise, and
   denied attempts are audited. Documented in the findings report.
3. **Audit append-only is ORM-layer.** No DB trigger / `NOUPDATE-DELETE` grant
   was added (SR-024 leftover). The Django layer has no update/delete path; the
   DB-role step stays a production-deployment grant (documented).
4. **`pip-audit` / `safety` are NOT AVAILABLE** (not installed); `pip check`
   (installed-dependency integrity) passes. A CVE scan of the lockfile remains a
   deploy/CI item.
5. **Emergency `rate_limit_ok` and analytics CSV JSON-envelope** are
   functional/INFO findings, outside the security fix scope; recorded only.
6. **`/admin/` + SessionAuth** remain (their own CSRF + session protections),
   unchanged by design — INFO.
7. **`scripts/setup_system_pg.sh`** dev-db password is staged in a script
   (dev-only) — INFO, not a production path (production consumes env vars only).
