## 1. Role-Based Post-Login Routing & Role Experiences

The backend is the authority for who a user is (`/auth/me` `role_codes`); the
frontend only uses those roles as a **routing hint**.

### 1.1 `primaryShellRoute` (`role_gate.dart`)

Login routing is now backend/role-driven (`login_page.dart` → `pushReplacementNamed`):

- `SUPER_ADMIN` / `ADMIN` → `/admin` (admin panel)
- `DOCTOR` → `/doctor-shell`
- `BLOOD_DONOR` → `/donor-shell`
- `CAREGIVER` → `/caregiver-shell`
- anything else (incl. PATIENT) → `/shell` (five-tab patient shell)

### 1.2 `RoleShell` (`lib/shared/widgets/role_shell.dart`)

A shared, adaptive shell base (same component family as the patient `MainShell`):
phone bottom `NavigationBar` / desktop `NavigationRail`, `IndexedStack` bodies,
optional global SOS `FloatingActionButton` (`tooltip: AppStrings.sos`, one FAB per
shell, `heroTag` per-role). Role users keep the global patient SOS path — there is
still exactly one SOS tooltip per shell and no second emergency system.

### 1.3 Doctor experience (`doctor_shell.dart` + `doctor_home_page.dart`)

- Tabs: **Doctor Home / Messages / Notifications / Profile**.
- `DoctorHomeView` is **fully real**: doctor messages come from the existing
  `/chat/` conversation list (via `ChatRepository`) and the unread badge from
  `/notifications/unread-count/` (via `NotificationsRepository`) — combined in
  `DoctorHomeRepository`. Honest empty/error states via `SkeletonListView`,
  `ErrorRetryView`, `EmptyStateView`.
- Sections that need backend surfaces that **do not exist yet** (appointments,
  patient requests, pending tasks, recent patient activity) show explicit
  "nothing here yet" states — no fabricated schedules or patients.

### 1.4 Blood Donor experience (`donor_shell.dart` + `donor_home_page.dart`)

- Tabs: **Donor Home / Blood / Notifications / Profile**.
- `DonorHomeView` reads the **real** donor profile (`/blood/donors/me`, incl.
  verified status), toggles availability via the existing `saveDonorProfile`
  (added `BloodDonorProfile.copyWith(isAvailable)`), lists **real** open blood
  requests (`/blood/requests/`, `is_open` filter) and links to the existing
  `DonorProfilePage` / `BloodRequestDetailPage`.
- Donor private contact details are never surfaced; all compatibility/matching
  stays backend-owned. Loading/empty/error states throughout.

### 1.5 Caregiver experience (`caregiver_shell.dart` + `caregiver_home_page.dart`)

- Tabs: **Caregiver Home / Community / Education / Profile**.
- Caregivers never see all patient information automatically. Linked-patient data
  appears only under backend authorization + consent; until then the home shows
  honest empty states (`EmptyStateView`), a real unread-notification badge from
  `/notifications/unread-count/`, and links to Caregiver Home messaging
  (authorized `/chat/` threads only), Community, Education and Notifications.

### 1.6 Admin routing fix

`AdminPanelPage` previously built with a hard-coded empty `roles: []`; it now
reads the session roles via `SessionScope.read(context)?.roles ?? const []`, so
the admin landing reflects the real session.
