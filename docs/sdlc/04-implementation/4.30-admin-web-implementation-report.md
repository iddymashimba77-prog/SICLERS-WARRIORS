## 1. What I found (audit)

- `apps/admin-web` was only a skeleton: `package.json` with empty metadata, a placeholder
  `AdminShell.tsx` (stubs), `design_tokens.ts`, empty README. No `package-lock`, no build.
- No framework was pinned by a lockfile. The skeleton used TypeScript (`AdminShell.tsx`),
  Node v24 + npm 11 were available, and the approved admin-web design docs referenced
  React Router → chose **React 18 + TypeScript + Vite**.
- **API prefix corrected:** the docs claim `/api/v1/`, but the implemented Django router
  mounts every app at `/api` (only health is `/api/v1/health/`). The Admin Web uses `/api`.
- Auth contract confirmed live: `POST /api/auth/login/` returns a **raw**
  `{access, refresh, user}` (not a `data` envelope) with `user.role_codes` +
  `user.permission_codes`; `/auth/refresh/` rotates; `/auth/me/` returns the same serializer;
  `POST /auth/logout/ {refresh}` → **205** and denies the refresh family.
- Admin list endpoints wrap results as `{"data":{"count,next,previous,results":[…]}}`.
- Some real URL asymmetries re-verified from the mobile repository (not guessed):
  - `/api/admin/facilities/{uid}/verify` — **no trailing slash**.
  - Blood verification queue lives at `/api/blood/requests/verification-queue/` (not
    `/api/admin/blood/…`).
  - Campaign approve/reject is one endpoint `POST /admin/campaigns/{uid}/verify` with
    `{approve, reason}` (not verify/reject).
  - `doctor suspend` is a distinct `POST /admin/doctors/{uid}/suspend` (not part of verify).
- News article deletion is backend-restricted to **DRAFT-only**; published articles use
  publish / unpublish / archive / feature (there is no delete). The web UI gates accordingly.
- Content category codes enforced by the backend: `HEALTH, BLOOD, COMMUNITY, EDUCATION,
  EVENTS, ANNOUNCEMENTS, FUNDRAISING`. Ticker types: `INFO, URGENT, BLOOD, EVENT,
  DONATION, SUCCESS`. Analytics granularity is uppercase `DAILY|WEEKLY|MONTHLY`, metric
  keys are dotted (e.g. `users.total`, `donations.confirmed_amount`).
- Dashboard KPI keys are underscore-shaped (`users_total`, `system_alerts_24h`, …) and
  role-adaptive. Financial summary fields are `confirmed_donations_*`, `refunded_total`,
  `pending_donations_count`, `active/closed/verified_campaigns_count`, `last_updated`.
- Permission codes (authoritative, from the mobile `admin_authz.dart`): `admin.users.manage`,
  `admin.roles.manage`, `admin.permissions.manage`, `admin.audit.read`, `audit_logs.view`,
  `audit_logs.export`, `analytics.view`, `analytics.export`, `content.news.manage`,
  `content.ticker.manage`, `education.review`, `community.moderate`, `donations.view`,
  `donations.refund`, `notifications.broadcast`, `doctors.verify`, `facilities.verify`,
  `blood_requests.verify`, `campaigns.verify`. Admin role hints: SUPER_ADMIN, ADMIN,
  VERIFICATION_OFFICER, MODERATOR, CLINICAL_ADMIN, CONTENT_ADMIN, FINANCE_ADMIN,
  SUPPORT_AGENT, SECURITY_AUDITOR.
- Throttle rates: `ContentWriteThrottle` 30/min, `ContentCoverThrottle` 10/min, global

## 5. Error-display rule (user directive, in Swahili)

Errors are rendered as readable warning text, never code lines or stack traces:
`ApiError` carves the backend `error.message` (normalizing the array/detail shapes),
classes produce `ErrorState` with a "Try again" retry, `ErrorBoundary` catches render
faults, calls fail to friendly messages via `friendlyError`, and fine-grained details are
logged to the console only. Reference log:

```
POST /api/auth/login/ wrong creds ->
{"error":{"code":"VALIDATION_ERROR","message":["Invalid credentials."],"details":{...}}}
```
renders as: "Invalid credentials." (no brackets, no trace).
