> applied**. Flutter **395 tests green**, `flutter analyze` clean.

## 1. Existing architecture discovered

- Backend is Django + DRF with apps under `backend/<domain>` mounted from
  `config/urls.py` under `/api/`.
- Authentication uses `accounts.User` with role rows (`UserRole` → `Role`) and
  permission codes (`user.has_perm_code(...)`). `User.is_admin` is true only for
  `ADMIN` / `SUPER_ADMIN`.
- The existing community app already provided posts, comments, reactions,
  reports and moderation. Notifications are a shared domain
  (`notifications.Notification`) with `type="COMMUNITY"`, `delivery_key`
  deduplication and `status`/`read_at`.
- Flutter is feature-first (`lib/features/<feature>/...`) with shared
  `AppColors`/`AppShapes`/`AppStrings`, repository classes wrapping `http`, and
  the logged-in Home dashboard in `features/home`.
- An earlier community implementation was already in the working tree; this
  work completes and verifies it without replacing existing models, permission
  codes or notification infrastructure.

## 4. Roles allowed and blocked

- **Allowed:** every active authenticated non-admin role (`PATIENT`, `SICKLER`,
  `DOCTOR`, `CAREGIVER`, `BLOOD_DONOR`, `FINANCIAL_DONOR`,
  `HEALTHCARE_STAFF`, `HOSPITAL`/`CLINIC`, `ORGANIZATION`,
  `VERIFICATION_OFFICER`, `MODERATOR`, etc.).
- **Blocked:** `ADMIN` and `SUPER_ADMIN`, enforced in
  `community.permissions.ForumMemberOnly` / `CommunityAccess` on every member
  endpoint. The Flutter Home action and Community route are also hidden for
  admin roles. Backend enforcement is authoritative; frontend hiding is not
  relied on.
- Object-level ownership: only the author (or a `community.moderate` holder)
  may edit/delete a post or comment. Locked posts reject new comments.

## 5. Notification behavior

- Created through the shared `notifications.services.create_notification`.
- Types stored in `data.forum_type`: `POST_COMMENT`, `COMMENT_REPLY`,
  `POST_ACTIVITY`, `POST_REACTION`.
- Recipients: discussion author, replied-to comment author, and prior
  participants (one notification per recipient per comment).
- Never notifies the actor about their own action, never notifies admin
  recipients.
- `delivery_key = community:comment:<comment_id>:<recipient_id>` makes creation
  idempotent (no duplicates on retries).
- Unread count is computed only from the authenticated user's `COMMUNITY`
  notifications, excluding `READ`/`SUPPRESSED`.
- No socket/push provider is configured, so the app uses load-on-open plus
  refresh-on-resume (`WidgetsBindingObserver`) rather than claiming real-time.

- Badge uses `data.forumUnreadCount` from
  `GET /community/notifications/unread-count/`; hidden at zero.

Safety: the feed shows “Community discussions are shared experiences, not
professional medical advice…”, the composer warns against private medical
details, author roles are backend-assigned, and content is rendered as plain
text after backend sanitisation.

## 7. Security & performance

- Authentication + role gates on every endpoint; admin denial is server-side.
- Ownership checks derive the actor from `request.user` (never body IDs).
- Parameterised ORM queries; `select_related` + annotated subqueries for counts
  (no N+1).
- Pagination via `CorePageNumberPagination` (20/page, max 100).
- Per-user throttles: post/comment/reaction/report 30/min; moderation 60/hour.
- Input length limits and allow-list HTML sanitisation; no attachments.
- Soft deletion keeps thread structure and moderation history.
- Comment depth capped at 5.

## 10. Known limitations / manual steps

- Migrations `0003` and `0004` must be reviewed and applied in each environment
  by the release owner; this work does not apply them.
- Notifications are refresh-on-open/resume, not push/socket; the existing push
  extension point (`notifications.services.deliver_push`) is untouched.
- Opening a notification navigates to the discussion but does not auto-scroll to
  the specific comment (comment id is available in notification `data` for a
  future enhancement).
- No file attachments by design (no secure upload/validation surface exists).
