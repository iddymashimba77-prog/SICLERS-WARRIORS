## 2. What was delivered

- **Global capped pagination (NFR-PERF-002).** `CorePageNumberPagination`
  (page 20 default, `?page_size=` honoured, hard cap 100) became the DRF default;
  the education **list** payload drops the full HTML body (detail keeps it);
  the analytics series scan is hard-bounded to 366 days.
- **Query-count discipline (NFR-PERF-001/SCAL-001).** Patient dashboard +
  adherence aggregation now batch medication-event counts in **one grouped
  query**; community feeds use correlated-subquery counts (constant per-post
  cost); AI monitoring aggregates in ≤ 2 `audit_log` queries; the admin emergency
  feed is `select_related` + bounded to the latest 100; broadcasts are a **single
  bulk INSERT** regardless of audience size.
- **Reference caching (privacy-safe).** Education categories served from cache
  (0 DB queries on 2nd hit; invalidate re-seeds); a strict "reference vocab
  only" policy means **no user-scoped data is ever cached**, and any cache
  failure falls back to the loader.
- **Async job queue (NFR-PERF-003).** Durable `BackgroundJob` table with
  exclusive `select_for_update` claim, stale-run re-claim, capped exponential
  backoff, max-attempts → FAILED, unknown task → FAILED; a `process_jobs`
  management command; first registered task `analytics.sync`.
- **Health observability (NFR-AVL-002).** Readiness does a **live cache
  set/get round-trip** and degrades to **503** if the cache is down (never 5xx,
  never fake-ok); every response carries `X-Duration-Ms` + `X-Query-Count`;
  opt-in duration/query logging.
- **Indexes.** Two additive indexes on proven hot filters (blood donor
  directory, education published/category feed); audited — no redundant indexes.
- **Guardian suite + harness.** New `performance` app (28 endpoint-level tests)
  and the reproducible `measure_perf_baseline` command whose baseline numbers
  feed this report.
- **Mobile efficiency.** Education bookmarks now fetch in parallel with
  per-article isolation; the education content list sends pagination params
  (parity with the backend).

## 4. Risks & carry-over (no silent divergence)

1. **LocMem is the default cache in ephemeral/test runs.** Production should
   set `CACHE_BACKEND=redis` (or the project's approved cache) via environment —
   the same code path, same reference-only keys, is production-neutral. Not
   actioned now because the runbooks/load goals are out of stage scope.
2. **Throttle/cache coupling.** If the cache backend becomes unavailable at
   runtime, rate-limiter bookkeeping can throw before views run (this is
   outside the health probe's own 503 handling). Mitigation is the same as
   above (a durable production cache); the health gate verifies the
   readiness-half of the contract.
3. **Async jobs run via a management command.** The queue is DB-backed and
   safe under concurrency, but no OS-level scheduler/daemon is wired in this
   stage — the 4.19+ deployment runbook owns multi-process scheduling.
4. **Baseline figures are relative, not absolute.** They are measured on an
   in-memory SQLite profile on the authoring machine; the p95 ≤ 500 ms target
   is verified against the query-count *invariants* (constant regardless of row
   volume), which is what the guardian suite enforces. Load-runbook numbers stay
   out of scope by the approved NFR threshold definition.
